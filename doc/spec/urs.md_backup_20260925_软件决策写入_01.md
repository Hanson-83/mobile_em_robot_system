## 1. 范围与边界

### 1.1 范围声明

本 URS **仅覆盖上位机软件系统**（服务器端 + 多类型客户端）。AMR、监测仪表、充电桩、电梯硬件、机械臂、采样机构、现场网络基建等由用户自行选型与交付；上位机通过**适配层契约**接入用户选定并保证可用的外部设备 API/协议。

### 1.2 In Scope（上位机）

- **服务器端软件**：任务/订单下发；原子技能与组合/集群任务编排；多机调度；状态与地图可视化后端；数据采集持久化；实时/历史趋势；点位管理；限值与报警；断点续传接收；报警事件；批报告；多用户/用户组/权限/安全策略；可开关审计追踪与电子签名；备份与灾难恢复；设备驱动网关/适配框架（抽象接口 + 配置装配，**不含具体硬件选型**）；多客户端后端与契约；对外 API。
- **客户端**：Vue Web（MVP）优先；桌面/移动可分期。
- **与已由用户选定的 AMR/仪表的软件集成契约**：API/协议适配器接口、Fake/Simulator、配置 schema、错误模型、坐标系/单位约定（具体型号字段留占位/配置驱动）。

### 1.3 Out of Scope / 用户负责

- AMR 厂家选型与商务、机械改装、充电桩硬件、电梯硬件改造。
- 粒子/温湿度/风速/浮游菌等仪表选型与采购；机械臂选型；采样机构机械设计；现场网络基建选型。
- 地面吸尘、拖地等清洁功能（**本系统不做清洁机**）。
- 正式合规认证/证书出具（如完整 IQ/OQ/PQ、第三方 Part 11 认证）— 本 URS 仅要求**取向与可开关能力**，认证范围 TBD。
- 选型清单、改装 BOM、他厂硬件参数对照作为选型结论的内容（文档中不作为本项目交付）。

### 1.4 分期（软件）

| 阶段 | 上位机交付重点 |
|------|----------------|
| MVP | 适配层 + Fake；任务编排与多机基础调度；地图/状态可视化；粒子/温湿度/风速**数据模型与采样命令**；报警；批报告；RBAC；审计/签名开关；备份；OpenAPI；Vue Web 客户端（MVP） |
| 扩展 | 浮游菌等仪表适配契约扩展；更丰富编排与看板；桌面/移动客户端增强 |
| 远期 | 协作臂/深度相机**软件技能与适配接口**（硬件由用户提供）；轨迹采样编排 |

## 2. 干系人与使用场景

| 角色 | 典型诉求 |
|------|----------|
| 洁净室/QA 运营 | 按计划自动巡检，数据可追溯，报警及时 |
| 设施/EHS | 温湿度、风速、粒子超限告警与趋势 |
| 制药验证/合规（如适用） | 审计追踪、电子签名可开关，数据完整性取向 |
| 系统集成/运维 | 适配多品牌设备（配置驱动）、备份恢复、日志可观测 |
| 开发/测试 | Fake/Simulator、OpenAPI、分层测试 |
| 管理层 | 多机效率、批报告、看板 |
| 用户（硬件 Owner） | 提供已选定设备的 API/协议文档与联调窗口 |

**主场景（MVP）**：运营在上位机编排「区域 A→B→C」监测任务 → 经适配层调度机器人导航至点位 → 触发仪表采样命令 → 数据上传与可视化 → 超限报警 → 任务结束生成批报告。

**扩展场景**：浮游菌采样任务编排；断网缓存后续传接收。

**远期场景**：经臂适配接口编排定点/轨迹采样（硬件就绪为前提）。

## 3. 术语

| 术语 | 说明 |
|------|------|
| AMR | Autonomous Mobile Robot，自主移动机器人（本 URS 中为**外部系统**） |
| 上位机 | 中央编排调度与数据中控软件（服务器 + 客户端）— **本 URS 交付主体** |
| 原子技能 | 不可再分的可执行动作（如导航到点、开始粒子采样） |
| 任务 | 由一组原子技能组成的可调度单元 |
| 组合任务 | 由多个任务按顺序/条件组成的工作流 |
| 集群任务 | 多机器人协同或并行的任务编排 |
| 适配层/网关 | 隔离业务与具体设备协议的驱动适配框架 |
| Fake/Simulator | 无硬件环境下的设备模拟实现 |
| 外部系统 | 用户选型并交付的 AMR/仪表/电梯等，经适配契约接入 |
| Part 11 | 21 CFR Part 11 取向（可开关能力，非已获证声明） |
| TBD | 待确认 |

## 4. 用户需求明细

优先级：`Must` / `Should` / `Could`。阶段：`MVP` / `扩展` / `远期`。

### 4.1 机器人软件能力与外部依赖假设

> 本节描述上位机须具备的**软件能力**，以及对用户交付机器人系统的**假设/依赖**。硬件能力本身不在本 URS 交付范围。

| ID | 描述 | 优先级 | 验收标准 | 阶段 |
|----|------|--------|----------|------|
| URS-ROB-001 | 上位机须通过适配层接入符合契约的 AMR（型号由用户提供/配置） | Must | YAML/配置可注册机器人；切换 Fake 与真实适配器无需改编排核心 | MVP |
| URS-ROB-002 | 上位机支持点位配置/管理、导航到点指令下发、位姿与状态订阅可视化 | Must | 可配置监测点；`navigate_to` 后状态机与地图位姿更新正确（真机依赖用户 AMR API） | MVP |
| URS-ROB-003 | 上位机支持充电/回充相关状态展示与 `dock_charge` 类技能调度 | Must | 低电量策略可配置触发；充电状态可从适配层上报并展示 | MVP |
| URS-ROB-004 | 适配层须覆盖连接、心跳、导航、取消、状态/遥测订阅等 AMR 契约方法 | Must | 接口清单有文档；Fake 与至少一种真实/录制适配器可跑通 | MVP |
| URS-ROB-005 | 上位机与边端/AMR 的通信会话可监测；断线有明确错误与重连策略 | Must | 离线产生事件；重连后任务可恢复或明确失败（见数据续传） | MVP |
| URS-ROB-006 | （依赖）用户保证机器人供电与仪表供电满足现场任务；上位机仅处理上报的供电/急停相关状态字段（若契约提供） | Should | 契约字段可配置映射；缺失字段不崩溃 | MVP |
| URS-ROB-007 | 电梯联动以**接口层技能**支持（Call/Enter/Exit）；是否进 MVP 验收包可配置豁免 | Should | 技能与状态机存在；无电梯 API 时 Fake 可演；真机依赖用户电梯方案 | MVP |
| URS-ROB-008 | （依赖）洁净室材质/等级由用户与 AMR 供应商保证；上位机不验收硬件材质 | — | 记入外部假设，非软件验收项 | — |
| URS-ROB-009 | 上位机可接收并展示急停/故障类安全状态（字段由契约定义） | Must | 急停/故障状态触发报警或任务中断策略可测（Fake 可注入） | MVP |
| URS-ROB-010 | 扩展仪表（如浮游菌）以适配器 + 配置扩展，不改调度核心 | Should | 新增适配器类型可注册并出现在技能目录 | 扩展 |
| URS-ROB-011 | 远期预留 ArmAdapter / DepthCameraAdapter 接口与技能占位 | Could | 接口与 Fake 骨架存在；非 MVP 阻塞 | 远期 |
| URS-ROB-012 | 远期支持臂定点/轨迹采样编排演示（依赖用户臂硬件与 API） | Could | Fake 演示：移动 → 臂到位 → 采样完成 | 远期 |

**外部依赖（用户保证）**：所选 AMR 提供可用的 SLAM/导航/充电/（可选）电梯 API 或等价协议；地图可导出或可同步至上位机显示层。

## 6. 假设与依赖（外部系统）

1. **用户负责** AMR/仪表/充电桩/电梯硬件/网络基建的选型、采购、改装与现场就绪。
2. 用户提供所选设备的 **API/协议文档、联调环境或仿真器**；适配器按文档实现。
3. 用户保证机器人具备（或将具备）SLAM/导航/充电/（可选）电梯等能力的可调用接口。
4. 现场 WiFi/VLAN 由用户 IT 提供；上位机侧实现断线检测与续传接收。
5. MVP 可不启用审计/电子签名即可完成主流程验收；制药试点再打开开关。
6. 他厂参考方案仅可借鉴**上位机侧**看板/数据上抛/任务流程思路；不引导本项目做清洁机或硬件选型。
