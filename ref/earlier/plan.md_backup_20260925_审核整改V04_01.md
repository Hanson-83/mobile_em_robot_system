## 1. 目标与里程碑

### 1.1 目标

交付可试点的上位机 MVP：任务编排与多机**简单互斥**调度、数据采集可视化、报警、批报告、权限与可开关审计/签名（**开启则批准流**）、设备适配层（含 Fake 与**电梯技能**）、**API Gateway** + OpenAPI 与 Vue Web 客户端（TypeScript + Vue）。真机联调（含电梯）作为**依赖用户硬件/API 就绪**的并行门禁，不阻塞 Fake 主路径。

### 1.2 里程碑（日期待排期）

| ID | 里程碑 | 完成标志（软件） |
|----|--------|------------------|
| M0 | 文档基线 | 上位机范围 URS/DS/方案/计划评审通过（含软件决策 V0.3） |
| M1 | 契约与骨架 | 适配接口草案、**API Gateway/OpenAPI** 草图、仓库骨架、Fake 冒烟（含电梯） |
| M2 | 调度 MVP | Fake 全链路：下发任务 → 模拟采样/电梯 → 看板/报警/报告；简单互斥可测 |
| M3 | 数据与合规 | 点位/限值/趋势、RBAC、审计/签名开关+**批准流**、备份恢复 |
| M4 | Web MVP 冻结 | URS-MVP Must（软件项）测试通过；电梯以 **Fake 验收**；真机联调不阻塞冻结 |
| M5 | Gateway 与多端契约 | OpenAPI 稳定版；MES/SCADA/DCS 对接能力；桌面/移动可分期立项 |
| M6 | 联调门禁 | 用户提供设备/电梯 API 后的适配器联调通过（并行） |
| M7 | 扩展 / 远期 | 浮游菌适配；交通管制增强；臂技能接口 PoC（软件） |

具体日历 **TBD**。真机相关日期依赖用户硬件就绪，与软件里程碑解耦记录。

## 4. 任务优先级与依赖

```text
文档评审(1) ─→ 契约与Fake(2) ─→ 调度+互斥+电梯(3) ─┬→ 数据看板(4) ─→ Web(6) ─→ MVP冻结(M4)
                     └→ API Gateway(7) ──────────────┤
                              └→ 权限审计批准流(5) ──┴→ Gateway稳定(M5) ─→ 多端(8)
用户设备/电梯API就绪 ────────────────────────────────→ 联调(9)〔并行门禁〕
测试(10) 贯穿 M1–M4（Fake）；HIL 跟 M6
交通增强(11) 在 MVP 后演进
```

优先级：

1. **P0**：适配层 + Fake 全链路（含电梯）、任务状态机、简单互斥、点位与时序、鉴权、**API Gateway** 草图。
2. **P0**：编排状态机草案、Vue Web（TypeScript + Vue）骨架。
3. **P1**：报警、批报告、地图可视化、断点续传接收。
4. **P1**：审计/签名开关、**批准流**、备份恢复、Gateway 对接能力（操作/数据/设置）。
5. **P2**：桌面/移动端；交通管制增强。
6. **P3**：浮游菌适配扩展、臂技能接口。
7. **并行**：用户硬件/电梯就绪后的真实适配器联调（不阻塞 Fake MVP）。

## 6. 测试方案

对齐 `spec/testing_quality.md`；**以 Fake/Simulator 为主路径**；真机联调为依赖用户硬件就绪的并行门禁。

### 6.1 分层策略

| 层级 | 范围 | 工具/方式 | CI |
|------|------|-----------|-----|
| 单元 | 解析、限值、状态机、错误模型、资源锁 | pytest | 默认跑 |
| 集成 | Gateway + API + 仓储；适配层 + **Fake**；批准流 | pytest + TestClient | 默认跑 |
| 端到端 / 冒烟 | 启动 → 下发任务 → Fake（含电梯）完成 → 报告/报警 | 脚本/compose | 关键冒烟 |
| 仿真 | 多机简单互斥冲突、断网续传 | Fake 注入 | 夜间可选 |
| HIL | 用户设备/电梯 API/真机 | 实验室/现场 | **默认跳过 CI**；跟 M6 |
| 验收 | URS 软件 ID 用例 | 验收记录表 | MVP 前 |

### 6.2 Fake / Simulator 要求（Must）

- `AmrFake`：导航耗时、电量、故障注入。
- `ParticleFake` / `ClimateFake` / `AirflowFake`：可配置曲线与超限。
- `ElevatorFake`：Call/Enter/Exit 可演；可注入失败。
- 配置切换真实适配器不改业务代码；MVP `access_mode=direct` 可测；未来 `via_edge_agent` 为扩展。

### 6.4 质量门禁（MVP）

- 软件 Must 级 URS 对应用例通过或有书面豁免（电梯真机可豁免，**电梯 Fake 不可豁免**）。
- CI 绿：单元 + 集成 + Fake 冒烟（含电梯路径）。
- Gateway、批准流（签名开）、简单互斥用例通过。
- HIL 不阻塞软件 MVP 冻结；通过后记入 M6。

## 7. 风险与缓解（软件侧）

| 风险 | 影响 | 缓解 |
|------|------|------|
| 用户设备/电梯 API 延期或不完整 | 真机联调推迟 | Fake 主路径（含电梯）；契约先行；录制回放适配器 |
| 未来切边端代理 | 续传与部署形态变化 | MVP 锁定直连（不上边端）；接口预留 via_edge_agent；边端须端侧缓存 |
| 前端框架已锁定 Vue | UI 技术选型已闭环 | 采用 TypeScript + Vue，按 Vue Web（MVP）实施 |
| 范围蔓延（清洁/硬件选型/臂） | 资源被抽走 | 严格上位机范围；臂走远期软件接口 |
| 合规期望过高 | 认证范围爆炸 | 「取向+开关」；开启签名强制批准流；非证书 |
| 多机冲突 | 调度复杂度 | **MVP 已定简单互斥**；增强单列演进 |
