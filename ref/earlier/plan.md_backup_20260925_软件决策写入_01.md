## 1. 目标与里程碑

### 1.1 目标

交付可试点的上位机 MVP：任务编排与多机可扩展调度、数据采集可视化、报警、批报告、权限与可开关审计/签名、设备适配层（含 Fake）、OpenAPI 与 Vue Web 客户端（TypeScript + Vue）。真机联调作为**依赖用户硬件/API 就绪**的并行门禁，不阻塞 Fake 主路径。

### 1.2 里程碑（日期待排期）

| ID | 里程碑 | 完成标志（软件） |
|----|--------|------------------|
| M0 | 文档基线 | 上位机范围 URS/DS/方案/计划评审通过 |
| M1 | 契约与骨架 | 适配接口草案、OpenAPI 草图、仓库骨架、Fake 冒烟 |

## 4. 任务优先级与依赖

```text
文档评审(1) ─→ 契约与Fake(2) ─→ 调度(3) ─┬→ 数据看板(4) ─→ Web(6) ─→ MVP冻结(M4)
                              └→ 权限审计报告(5) ─→ 对外API(7) ─→ 多端(8)
用户设备API就绪 ──────────────────────────────→ 联调(9)〔并行门禁〕
测试(10) 贯穿 M1–M4（Fake）；HIL 跟 M6
```

优先级：

1. **P0**：适配层 + Fake 全链路、任务状态机、点位与时序存储、鉴权。
2. **P0**：OpenAPI 草图、编排状态机草案、Vue Web（TypeScript + Vue）骨架。
3. **P1**：报警、批报告、地图可视化、断点续传接收。
4. **P1**：审计/签名开关、备份恢复、对外 API。
5. **P2**：多机策略增强、电梯技能验收策略、桌面/移动端。
6. **P3**：浮游菌适配扩展、臂技能接口。
7. **并行**：用户硬件就绪后的真实适配器联调（不阻塞 Fake MVP）。

## 6. 测试方案

对齐 `spec/testing_quality.md`；**以 Fake/Simulator 为主路径**；真机联调为依赖用户硬件就绪的并行门禁。

### 6.1 分层策略

| 层级 | 范围 | 工具/方式 | CI |
|------|------|-----------|-----|
| 单元 | 解析、限值、状态机、错误模型 | pytest | 默认跑 |
| 集成 | API + 仓储；网关 + **Fake** | pytest + TestClient | 默认跑 |
| 端到端 / 冒烟 | 启动 → 下发任务 → Fake 完成 → 报告/报警 | 脚本/compose | 关键冒烟 |
| 仿真 | 多机冲突、断网续传 | Fake 注入 | 夜间可选 |
| HIL | 用户设备 API/真机 | 实验室/现场 | **默认跳过 CI**；跟 M6 |
| 验收 | URS 软件 ID 用例 | 验收记录表 | MVP 前 |

### 6.2 Fake / Simulator 要求（Must）

- `AmrFake`：导航耗时、电量、故障注入。
- `ParticleFake` / `ClimateFake` / `AirflowFake`：可配置曲线与超限。
- 配置切换真实适配器不改业务代码。

### 6.4 质量门禁（MVP）

- 软件 Must 级 URS 对应用例通过或有书面豁免。
- CI 绿：单元 + 集成 + Fake 冒烟。
- HIL 不阻塞软件 MVP 冻结；通过后记入 M6。

## 7. 风险与缓解（软件侧）

| 风险 | 影响 | 缓解 |
|------|------|------|
| 用户设备 API 延期或不完整 | 真机联调推迟 | Fake 主路径；契约先行；录制回放适配器 |
| 边端拓扑久拖不决 | 续传实现返工 | 先定接口，实现可插拔两种部署 |
| 前端框架已锁定 Vue | UI 技术选型已闭环 | 采用 TypeScript + Vue，按 Vue Web（MVP）实施 |
| 范围蔓延（清洁/硬件选型/臂） | 资源被抽走 | 严格上位机范围；臂走远期软件接口 |
| 合规期望过高 | 认证范围爆炸 | 「取向+开关」非证书 |
| 多机冲突策略不清 | 调度返工 | MVP 简单互斥；增强单列 |
