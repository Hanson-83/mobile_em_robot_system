## 1. 总体方案与分期

### 1.1 定位

构建「**上位机自研**」的移动环境监测中控软件：编排调度用户选定的 AMR/仪表完成到点采样，提供数据持久化、看板、报警、批报告、权限与可开关合规能力。

**明确不做**：

- 吸尘/拖地等清洁功能。
- **硬件设备选型与采购**（AMR、仪表、充电桩、电梯改造、机械臂、采样机构、网络基建）— 由用户负责。
- 本方案不输出选型清单或改装 BOM。

### 1.2 分期（软件交付物）

| 阶段 | 软件交付物 | 外部依赖（用户） |
|------|------------|------------------|
| MVP | 适配网关 + Fake；调度编排；数据看板；报警；批报告；RBAC；审计/签名开关；备份；OpenAPI；Vue Web 客户端（MVP） | 用户提供设备 API/仿真或后续真机联调窗口 |
| 扩展 | 浮游菌等适配契约；编排增强；桌面/移动客户端 | 用户扩展仪表就绪 |
| 远期 | 臂/深度相机技能与适配接口 | 用户臂硬件与 API |

### 1.3 架构一句话

单体模块化上位机（Python FastAPI + TypeScript + Vue 前端）经**设备适配网关**连接符合契约的外部 AMR/仪表；配置 YAML；合规能力可开关；开发以 Fake 为主路径。

**前端选型已锁定：Vue 3 + TypeScript + Vite，交付形态为 Vue Web（MVP）；本项目覆盖默认规范中的前端选型。**

## 2. 外部系统与集成假设

> 本章替代原「AMR 选型与改装」「仪表型号对照」章节。仅描述上位机集成所需假设，**非选型结论**。

### 2.1 用户负责的外部系统

| 外部系统 | 用户职责 | 上位机侧期望 |
|----------|----------|--------------|
| AMR | 选型、商务、改装、充电桩、洁净材质 | 文档化 API：导航、状态、充电、地图/点位同步；可选电梯 |
| 粒子/温湿度/风速等 | 选型、采购、安装供电 | 可远程启停/读数或等价协议；参数进 YAML |
| 电梯/楼控 | 硬件改造与协议开放 | 若启用，提供可调用接口供适配器封装 |
| 现场网络 | WiFi/VLAN/隔离 | 可达性；软件侧超时与续传 |
| 协作臂（远期） | 选型与安装 | Arm/Camera API 供适配 |

### 2.2 集成契约（软件）

- 适配器接口见 `doc/spec/ds.md` §4.1。
- 配置 schema：`robots[]` / `instruments[]` / `features{}`；型号字段为字符串占位，由用户填写。
- 错误模型与坐标系/单位约定在适配边界统一。
- Fake/Simulator 与真实适配器实现同一接口。

### 2.3 他厂参考（仅上位机可借鉴）

可借鉴思路：**任务流程编排、数据上抛与看板呈现、报警与批报告形态**。

**删除/不采用**：引导本项目做清洁机；将他厂硬件参数/型号作为本项目选型结论；改装 BOM 照搬。

## 3. 监测数据与采样命令（软件）

### 3.1 原则

- 通讯与型号差异收敛在适配层 + YAML。
- 每种仪表：真实适配器（用户文档就绪后）+ Fake。
- 点位绑定 instrument profile 与限值；超限复测可作为组合任务模板。

### 3.2 MVP 数据域

| 指标 | 领域命令 | 配置占位 |
|------|----------|----------|
| 粒子 | start/stop/read_channels | adapter_type, endpoint/port, channel_defs |
| 温湿度 | read_temp_humidity | adapter_type, unit, precision |
| 风速 | read_air_speed | adapter_type, unit |

扩展：浮游菌参数（时长/流量等）配置化。

## 4. 上位机软件方案

### 4.1 模块

见 `doc/spec/ds.md`：API、调度、数据、报警、报表、鉴权、适配网关、审计/签名、备份、前端。

### 4.2 推荐模块目录（单体仓库）

```text
mobile_em_robot_system/
  backend/
    app/
      api/           # 路由 / OpenAPI
      domain/        # 任务、点位、报警等领域
      adapters/      # AMR/仪表/仓储实现（含 fake/）
      services/      # 调度、报表、备份
      core/          # 配置、安全、错误模型
    tests/
    pyproject.toml   # uv
  frontend/
    src/
  config/
    devices.example.yaml
    features.example.yaml
  doc/
  ref/
  spec/
  deploy/
    docker-compose.yml
```

### 4.3 适配网关

- `AdapterFactory` 按 `type` 装配。
- 统一生命周期：`start/stop/health`。
- 遥测归一化为领域 DTO。
- 集成测试：网关 + Fake。

### 4.4 配置示例（示意）

```yaml
# config/devices.example.yaml
robots:
  - id: robot-01
    adapter: amr_fake   # 用户就绪后改为 amr_vendor_x 等
    endpoint: "http://192.168.x.x/api"
    # model: "<user-provided>"
instruments:
  - id: pc-01
    robot_id: robot-01
    adapter: particle_fake
    # model: "<user-provided>"
    # port: /dev/ttyUSB0
features:
  audit_trail: false
  e_sign: false
  elevator_skills: false   # 接口可存在；验收是否启用另定
```

## 5. 地图 / 点位 / 调度（软件）

1. **地图**：导入或同步用户 AMR 厂工具产出的地图/等价表示；上位机显示层标准化。
2. **点位**：地图标注；JSON/YAML 导入导出；任务引用。
3. **调度**：
   - MVP：单机队列 + 多机简单并行（资源锁：点位/电梯技能/充电桩逻辑资源）。
   - 冲突：先互斥锁；完整车队交通 **TBD**。
4. **电梯**：独立技能；无外部 API 时用 Fake；真机依赖用户。
5. **充电**：电量阈值触发 `DockCharge`（依赖状态字段由适配层提供）。

## 6. 数据与看板

| 能力 | 方案要点 |
|------|----------|
| 实时 | WS/SSE 推送测量与位姿 |
| 历史 | 查询 API + 图表 |

## 8. 环境与部署（服务器/客户端）

- **服务器**：Ubuntu LTS 优先；配置随并发评估（小规模参考值不写入承诺）。
- **运行**：`uv sync` + systemd 或 Docker Compose。
- **客户端**：现代浏览器；桌面/移动分期。
- **时间同步**：NTP。
- **备份**：DB + 配置 + 报告；异地策略 TBD。
