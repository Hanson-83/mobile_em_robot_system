## 2. 总体评价

本分支在 **P0a** 方向交付完整度较高：`backend/app/adapters/` 下 Amr / Particle / Climate / Airflow / **Elevator** 协议与 Fake 实现清晰，`AdapterFactory` 强制 MVP `access_mode=direct` 并拒绝 `via_edge_agent` 与 vendor 占位装配；`ElevatorAdapter` 与 `AmrAdapter` 边界与 DS §4.1、plan §6.2 一致。FastAPI Gateway 以 `operations` / `data` / `settings` 三分组暴露 OpenAPI，集成测试覆盖鉴权、RBAC、`e_sign` 默认与批准拦截、幂等与 `/ready` 适配器健康；Vue 骨架具备登录、地图壳（拉 `/robots`、`/maps`）、任务列表及 plan §3.1 占位路由，符合 M1「草图 + 骨架」定位。

主要短板不在电梯模型或目录权威（已对齐 V0.4 决议），而在 **对外契约草图与 DS §4.2 最小资源表尚未对齐**（点位 DELETE、用户 POST 等缺失）、**安全规范与实现之间的默认口令/JWT 默认值**（虽无真实密钥入库，但源码与 compose 默认仍偏松）、以及 **Gateway 限流无自动化证明**。`doc/test.md` 已记录 M1 冒烟，但 `ref/progress.md` 仍标 M1 进行中，里程碑行政闭环待本审核整改后更新。

## 3. 符合项（做得好的地方）

- **ElevatorAdapter 独立**：`elevator/protocol.py` + `ElevatorFake` 提供 Call/Enter/Exit；`AmrAdapter` / `AmrFake` 无电梯方法，单测显式断言（`test_adapters_fake.py`）。
- **access_mode=direct**：`devices.example.yaml` 与 `InstrumentConfig` 默认 `direct`；`AdapterFactory._check_access_mode` 对 `via_edge_agent` 校验失败。
- **e_sign 默认 false**：`FeaturesFile.e_sign` 默认 `False`；`config/features.example.yaml` / `devices.example.yaml` 一致；Gateway `GET /settings/features` 与 `test_gateway.test_points_and_robots` 断言；开启时 `PATCH /settings/limits` 返回 `APPROVAL_REQUIRED`。
- **OpenAPI 三分组**：`main.py` `OPENAPI_TAGS` + 三 Router；`test_openapi_groups` 断言 tags 集合与关键路径。
- **目录权威 scheme §4.2**：`backend/app/{api,domain,adapters,services,core}`、`backend/tests`、`config/`、`frontend/src`、`deploy/`；**无**仓库顶层 `adapters/`。
- **Fake 可测且 CI 友好**：电梯冒烟（Call/Enter/Exit、失败注入、锁服务协作）、仪表与 AMR 急停注入；`.github/workflows/ci.yml` 含 ruff + pytest + 前端 typecheck/build。
- **秘钥未入库（真实机密）**：`.gitignore` 含 `.env`；`deploy/.env.example` 仅占位；未发现生产级密钥文件提交；设备 endpoint 为示意占位。
- **配置驱动装配**：`devices.example.yaml` 含 `robots` / `instruments` / `elevators[]`；vendor 类型工厂层拒绝并提示等待用户 API。
- **错误模型与权限码**：`DomainError` 体与 DS 错误码初稿对齐；`security.ROLE_PERMS` 注释对齐 DS §4.2。
- **资源锁骨架**：`LockService` + `RESOURCE_ORDER` 单测；与电梯冒烟测试结合，为 M2 编排打底。
- **前端仅经 Gateway**：`api/client.ts` 相对路径调 `/api/v1/*`，路由覆盖 plan §3.1 页面壳。
