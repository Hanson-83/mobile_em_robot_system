## 2. 总体评价

M1 把对内适配与对外 Gateway 拆开了。`AmrAdapter` 只有导航、充电、遥测与急停相关方法；`ElevatorAdapter` 单独提供 `call_elevator` / `enter_elevator` / `exit_elevator`。`AmrFake`、`AmrRecorded`、`AmrVendorX` 都没有电梯方法。厂商类在 `connect` 时抛出 `DEVICE_OFFLINE`，健康检查为未连接，没有伪造协议帧。示例配置为 `access_mode: direct`，电梯为 `elevator_fake`。

Gateway 运行时具备 Bearer 会话与 API Token、权限码、`{code, message, retryable, details?}` 错误体，以及每分钟窗口限流。DS §4.2 最小资源表里的 HTTP 路径，除方法集合有少量缺口外，多数已经挂在 `/api/v1` 下，并带 `operations` / `data` / `settings` 标签。`Measurement.idempotency_key` 有唯一约束，生成规则与 DS §5.1 一致（优先 `client_request_id`，否则 `sha1(device_id|sample_id|ts_iso)`）。

契约交付物本身还不闭合。提交的 `backend/openapi/openapi.json` 与按当前路由生成的文档都不会声明安全方案，422 仍写成 FastAPI 的 `HTTPValidationError`，而处理器实际返回领域错误体。WebSocket 路由存在，但不在 OpenAPI 中，且只在客户端再发消息时回放历史事件。`test_m1_contract.py` 覆盖了 401/403、路径键、Fake 切换和电梯三动作，没有覆盖限流、错误体外形、电梯/仪表厂商拒绝连接，也没有覆盖 OpenAPI 与实现的差异，因此测试通过不能证明 TC-MVP-08 的契约已对齐。

## 6. 一致性问题

- DS 资源表路径参数写作 `{id}`，实现与 OpenAPI 为 `{task_id}`、`{alarm_id}`、`{point_id}`。语义相同，生成客户端的字段名不同。
- 口令错误与未携带令牌都返回 `AUTH_REQUIRED`（`routes.py` 171 行与 138 行）。DS 对该码的解释是「未鉴权」。
- 批准请求过期使用 `APPROVAL_REJECTED`（`routes.py` 693 行）。DS 对该码的解释是「已驳回」，没有单独的过期码。
- `/skills`、`/metrics` 的 OpenAPI 标签与权限码不在同一分组（M1-010）。
- `devices.example.yaml` 的 `features` 与 `config/features.example.yaml` 重复。`main.py` 39–40 行以后者覆盖前者。当前两份值一致，后续若只改一处会分叉。
- `AmrRecorded` 继承 `AmrFake` 并覆盖初始状态（`recorded.py` 12–28 行），不是独立协议回放器。作为「录制适配器路径」可接受，但不要在文档里写成厂商报文回放。
- scheme §4.2 将领域对象放在 `domain/`。当前 `domain/dto.py` 是状态与读数 DTO，任务/点位/报警/批准的表在 `adapters/orm.py`。这与「仓储实现放在 adapters」不冲突，领域包本身还不是实体层。

## 7. 优先整改清单

1. M1-001、M1-002：让 OpenAPI 与运行时的鉴权、统一错误体一致，并重新导出 `backend/openapi/openapi.json`。
2. M1-003：限流按已验证主体或匿名桶计数，堵住随机 Bearer 换桶。
3. M1-004：WebSocket 改为订阅后的持续推送，并写进对外契约。
4. M1-005：把上述行为写成会失败的测试，避免只断言路径键。
5. M1-006：在后续迭代补超时与重连；在此之前追溯矩阵不要勾选 URS-ADP-002 关闭。
6. M1-007、M1-008 可随契约补测一并改，优先级低于前四项。

## 8. 后续验证关注点

- TC-MVP-08：未鉴权、越权、合法 Bearer、合法 API Token、429 错误体、OpenAPI 安全方案与错误 schema 应在同一条契约用例里能复核。
- TC-MVP-10：电梯厂商与三种仪表厂商的 `connect` 必须失败；`AmrAdapter` 协议与 `AmrVendorX` 均不得出现电梯方法。
- TC-MVP-15：默认配置全为 `direct`。若配置写成 `via_edge_agent`，健康检查不得报告边端可用。
- 订阅 WebSocket 之后再发布 `pose`/`task`/`alarm`/`measurement`，确认连接保持期间能收到，且主题过滤有效。
- 幂等回放与 `IDEMPOTENCY_REPLAY` 现由 M2 测例覆盖，回归时不要从 M1 契约里删掉数据模型约束。
- C-05、C-06、C-07、C-14 在用户改口之前维持占位，不要因「未接真机 / 未做 PDF / 开发库为 SQLite / 无边端进程」再开 P0。
