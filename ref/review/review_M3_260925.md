# M3（RBAC、审计、批准流、备份恢复）审核意见

## 1. 审核元信息

- 审核人：Reviewer_M3（独立审核）
- 审核日期：2026-09-25
- 审核对象：移动环境监测机器人上位机 Fake MVP M3
- 审核依据：`doc/spec/ds.md`、`doc/spec/urs.md`、`ref/plan.md`、`spec/security.md`
- 实际检查：指定的 M3 代码、ORM、测试与 `config/features.example.yaml`
- 总体结论：**不通过**。发现 4 项 P0、3 项 P1、1 项 P2；批准流核心限值路径、显式权限检查和 SQLite 引擎重绑已实现，但 RBAC、审计完整性及备份恢复尚未满足全部 Must。
- 验证限制：已尝试运行 M3 定向测试，但环境中 `pytest` 与 `uv` 均不可用，故本次结论以逐行静态审核为主；不得把仓库 `doc/test.md` 中的“通过”记录视为本审核已独立复现。

## 2. 总体评价

实现采用显式权限字符串和精确匹配，没有通配符；`viewer` 不含任务写权限和审计读取权限。`e_sign=false` 默认值正确，限值和报告批准可直接生效；开启后均创建 `Pending` 请求并返回 `409 APPROVAL_REQUIRED`，密码复核后单步决定，拒绝不应用，TTL=0 被明确构造为已过期。SQLite 使用在线 backup API，恢复后执行引擎重绑。

主要缺口是：用户组没有参与授权且权限不可配置；没有自动备份；报告直接批准和关闭审计开关本身可不留审计记录；自定义活动 YAML 路径恢复到错误位置。这些分别触及 URS-SEC-001、URS-BAK-001/002、URS-AUD-001 的 Must。

## 3. 符合项

- `backend/app/services/bootstrap.py:11-37,39-58`：权限均为显式字符串，无 `*`；`viewer` 无 `operations.task.write`、无 `settings.audit.read`。
- `backend/app/api/routes.py:157-163`：授权采用权限字符串精确包含判断；任务写、用户/组、审计、批准、备份等路由均声明对应权限。
- `config/features.example.yaml:1-3` 与 `backend/app/services/support.py:33-48`：`e_sign` 默认 `false`。
- `backend/app/api/routes.py:560-584,439-452`：签名关闭时限值变更、报告批准立即生效；开启时创建批准请求并返回 409。
- `backend/app/api/routes.py:655-720`：批准为单步；仅用户会话可签名；复核当前用户口令；拒绝不调用领域应用；过期不生效；TTL=0 立即过期。
- `backend/app/adapters/repository.py:475-506`：审计仓储仅暴露追加与查询；路由没有审计 DELETE，框架对 `DELETE /api/v1/audit` 返回 405。
- `backend/app/services/backup.py:80-89`：SQLite 使用 `sqlite3.Connection.backup()`，不是运行中数据库文件的直接热拷贝。
- `backend/app/services/backup.py:55-76`、`backend/app/main.py:45-50`：SQLite 恢复后重建 engine/session/repository，并重绑 scheduler 与 feature service。
- 开发种子口令只在 `dev_seed` 开启时建立，源码与界面均提示生产关闭；未发现私钥、云访问密钥或高置信度真实 Token。开发口令不评价为生产安全。
- PostgreSQL 采用手工 `pg_dump` 的部署说明按本次审核规则不判缺陷。

## 6. 一致性

- URS、DS、plan 与示例配置对 `e_sign=false` 默认值、开启后强制批准流、单步 MVP、72h 默认 TTL 的描述一致。
- 权限命名与 DS API 表基本一致，且实现没有通配符；viewer 的实际权限符合重点核对要求。
- DS 要求审计 DB 角色仅 INSERT+SELECT，当前部署实现未落地，与实现不一致。
- URS 要求自动与手动备份，当前 API/代码仅手动，与实现不一致。
- `doc/test.md` 对 TC-MVP-06/07/09/13/21 的“通过”表述宽于真实测试断言，与证据不一致。
- 自批准、开发种子口令、HTTP 非 TLS 已列入 `ref/待确认事项_260925.md`；本审核仅作观察，不重复判 P0。

## 7. 优先整改清单

1. 完成可配置 RBAC 授权链，确保组真正参与有效权限计算。
2. 修复审计旁路：报告批准与关闭审计开关必须留痕。
3. 增加自动备份，并修复活动 YAML 恢复目标；补配置、报告和失败恢复验证。

5. 落实数据库级审计防篡改，再补齐权限矩阵和报告批准测试。
